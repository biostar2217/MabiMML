# MabiMML 의견 받기 서버 지시문

아래 내용을 남븝캘린더 웹서버(nambebmabi.com)를 맡은 Claude 에게 그대로 전달한다.
앱 쪽 구현은 `src/feedback.rs` (v3.0.1 이후). 형식을 바꾸면 양쪽을 같이 고쳐야 한다.

---

마비노기 MML 변환기(MabiMML, Windows 데스크톱 앱)에 "의견 보내기" 기능이 들어갔어. 앱이 사용자의 버그 제보·기능 제안을 우리 웹서버로 보내니까, 받는 엔드포인트를 만들어 줘. 기존 AI 중계(`POST /mabimml/ai`)와 같은 서버·같은 스타일로 만들면 돼.

## 1. 주소
`POST https://nambebmabi.com/mabimml/feedback`
(HTTPS 필수. 다른 주소로 하게 되면 알려 줘. 앱의 `FEEDBACK_URL` 상수만 바꾸면 된다.)

## 2. 요청
헤더:
- `Content-Type: application/json; charset=utf-8`
- `User-Agent: MabiMML/<버전>`
- `X-MabiMML-Version: <버전>` (예: `3.0.1`)

본문 (JSON, 모든 필드가 항상 온다. 선택 항목은 빈 글자 `""`):
```json
{
  "app": "MabiMML",
  "version": "3.0.1",
  "kind": "bug",
  "message": "이 곡을 열면 화음2가 비어 나와요",
  "contact": "디스코드 nambeb",
  "song": "golden-hour.mid",
  "mml": "MML@t120cde,...;\n\nMML@...;",
  "os": "windows x86_64",
  "client_id": "7a43959fd46f4e5a0fb0329bc5d4a0cc"
}
```
| 필드 | 뜻 | 검사 |
|---|---|---|
| app | 항상 `"MabiMML"` | 다르면 400 `bad_request` |
| version | 앱 버전 | 문자열, 최대 20자 |
| kind | `bug`(버그 제보) / `idea`(기능 제안) / `other`(기타) | 이 셋이 아니면 `other` 로 저장 |
| message | 사용자가 쓴 내용 (필수) | 앞뒤 공백 뺀 뒤 비면 400 `empty`, 3000자 넘으면 413 `too_large` |
| contact | 답장 받을 곳 (선택: 이메일·디스코드·게임 닉네임 등 자유 글) | 최대 100자 |
| song | 곡 파일 이름 (사용자가 "MML 함께 보내기"를 켰을 때만) | 최대 200자 |
| mml | 변환된 MML 전체 (같은 경우만, 장 사이는 빈 줄) | 최대 20000자 |
| os | 운영체제 | 최대 40자 |
| client_id | PC마다 한 번 만든 무작위 32자리 16진수 (개인정보 아님) | 형식이 다르면 무시하고 빈 값으로 |

글자 수는 바이트가 아니라 글자(코드포인트) 기준. 요청 본문 전체는 64KB 를 넘으면 413 으로 거절.

## 3. 응답 (항상 JSON)
- 성공: 상태 200, `{"ok": true, "id": "fb_123"}`
  `id` 는 접수 번호(문자열 또는 숫자). 앱이 "보냈어요. 접수 번호: fb_123" 로 보여 준다.
- 실패: `{"ok": false, "error": "<코드>", "message": "<사람이 읽을 설명>"}`, 상태 코드는 아래와 같이:
  - 400 `bad_request` (JSON 이 아니거나 app/필드 모양이 틀림), 400 `empty` (내용 없음)
  - 403 `bad_request` (`X-MabiMML-Version` 헤더 없음)
  - 413 `too_large`
  - 429 `rate_limited`
  - 503 `disabled` (기능을 잠시 끈 경우, 환경 변수 하나로 끌 수 있게)
  - 500 그 밖의 서버 오류
앱은 `error` 코드로 한국어 안내를 고른다. 위 코드 이름은 꼭 그대로 써 줘.

## 4. 저장
- DB 테이블(또는 SQLite/JSONL 파일) 하나에 저장: `id, created_at(UTC), kind, message, contact, song, mml, version, os, client_id, ip_hash, status`
  - `status` 는 `new` / `read` / `done` (관리 화면에서 바꿀 수 있게)
  - IP 는 원문 대신 솔트를 넣은 해시로 저장 (도배 확인용). 원문 IP 는 저장하지 않는다.
- 저장한 글을 HTML 로 보여 줄 때는 반드시 이스케이프 (사용자 글이 그대로 들어온다).

## 5. 내가 확인하는 방법
- 관리 화면: `https://nambebmabi.com/mabimml/feedback/admin` (기존 사이트 관리자 로그인이 있으면 그걸로, 없으면 환경 변수의 긴 비밀번호로 보호)
  - 최신순 목록: 날짜, 종류, 내용 앞부분, 연락처, 버전, 상태
  - 눌러서 전체 보기 (MML 은 접어 두고 "복사" 버튼), 상태 바꾸기, 삭제
  - 종류·상태로 거르기
- (선택) 새 의견이 오면 알림: 디스코드 웹훅 주소를 환경 변수에 넣으면 종류·내용 앞 200자·연락처를 보내 준다. 웹훅이 실패해도 접수는 성공으로 응답.

## 6. 도배·스팸 막기
- 횟수 제한: IP 당 10분에 3회, 하루 20회. `client_id` 당 하루 20회. 넘으면 429 `rate_limited`.
- 전체 하루 500건 넘으면 429 (폭주 방지).
- `X-MabiMML-Version` 헤더 없으면 403. `app` 이 `MabiMML` 이 아니면 400.
- 같은 `client_id`(없으면 IP 해시)가 같은 `message` 를 10분 안에 다시 보내면 새로 저장하지 말고 이전 `id` 로 200 성공 응답 (앱의 재시도·두 번 누르기 대비).
- 본문 64KB 제한, 필드별 글자 수 제한(위 표).
- 앱 전용이니 CORS 헤더는 열지 않는다 (브라우저에서 못 부르게).

## 7. 시험
만들고 나면 이걸로 확인해 줘:
```bash
curl -s -X POST https://nambebmabi.com/mabimml/feedback \
  -H "Content-Type: application/json; charset=utf-8" \
  -H "X-MabiMML-Version: 3.0.1" \
  -d '{"app":"MabiMML","version":"3.0.1","kind":"bug","message":"시험 전송입니다 (지워도 됨)","contact":"test","song":"","mml":"","os":"windows x86_64","client_id":"0123456789abcdef0123456789abcdef"}'
```
→ `{"ok":true,"id":...}` 가 와야 하고 관리 화면에 보여야 한다. 헤더를 빼면 403, message 를 `""` 로 하면 400 `empty`, 내용을 조금씩 바꿔 10분 안에 4번 보내면 429, 같은 내용을 두 번 보내면 같은 id 가 와야 한다.
앱 쪽에서는 `MABIMML_FEEDBACK_URL=https://nambebmabi.com/mabimml/feedback cargo test --lib live_send -- --ignored --nocapture` 로 실제 전송을 시험할 수 있다.

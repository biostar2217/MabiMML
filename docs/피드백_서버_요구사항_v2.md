# MabiMML 피드백 게시판 서버 변경 지시문 (v2, 2026-11-19)

아래를 nambebmabi.com 웹서버를 맡은 Claude 에게 그대로 전달한다. 서버 반영(배포)은 사용자 허락 뒤에.

## 배경
MabiMML 앱의 '피드백 보내기' 창이 게시판 형식으로 바뀌었다(앱 소스 `_rust_git/src/feedback.rs`, 아직 릴리스 전).
목록(번호·분류·제목·글쓴이 닉네임·날짜·상태·답변) → 글 보기(전체 글 + 제작자 답변) → 글쓰기(닉네임 선택·분류·내용·답장 받을 곳·MML 함께 보내기).
**본인 글만 보이고**, 다른 사람 글은 관리자(제작자)만 본다.

지금 실서버(v1, 2026-11-18 반영, `mabimml_feedback.py`)에 이미 있는 것:
- `POST /mabimml/feedback` 글쓰기, `POST /mabimml/feedback/mine` 본인 글 목록 + 답변, `/mabimml/feedback/admin/*` 관리자 API(답변 달기 포함)
- 2026-11-19 확인: `/mine` 은 `{"ok":true,"items":[]}` 로 살아 있음

v1 에 **없는 것** (이번 변경):
1. 닉네임(`nickname`) 저장·반환
2. 분류 `question`(질문)
3. 인증값(`client_id`) 원문 대신 해시 저장
기존 주소·JSON 모양·오류 코드는 그대로 두고 **추가만** 한다. v1 앱(3.1.0)도 계속 그대로 동작해야 한다.

## 1. 글쓰기 `POST /mabimml/feedback` — 필드 추가
앱이 보내는 본문(새 필드 `nickname`, `kind` 에 `question` 추가):
```json
{"app":"MabiMML","version":"3.1.1","nickname":"남븝팬","kind":"question","message":"...","contact":"","song":"","mml":"","os":"windows x86_64","client_id":"<32자리 16진수>"}
```
- `nickname`: 문자열, 없거나 null 이면 빈 값. 제어 문자는 공백으로, 앞뒤 공백 제거, **20자(코드포인트)까지 잘라** 저장. 비면 `"익명"` 으로 저장. (앱도 비면 "익명" 을 보내지만, v1 앱은 이 필드를 안 보내므로 서버에서도 "익명" 으로 채운다.) 길다고 오류 내지 말 것.
- `kind`: `bug` / `idea` / `question` / `other`. 그 밖은 `other`.
- 나머지 검사·횟수 제한·중복 방지·응답은 v1 그대로.

DB: `items` 에 `nickname TEXT NOT NULL DEFAULT '익명'` 열 추가 (기존 행은 '익명').

## 2. 인증값 해시 저장
`client_id` 는 PC마다 한 번 만든 비밀값이고 `/mine` 에서 본인 확인에 쓰이니, 서버에 원문을 두지 않는다.
- `items` 에 `client_hash TEXT NOT NULL DEFAULT ''` 열 추가: 서버 솔트를 넣은 `sha256(salt + ":client:" + client_id 소문자)` (형식이 틀린 값이면 빈 값). 2026-11-19 구현: `캘린더 베타용 서버/.updates/mabimml-feedback-v2-20261119/new`
ew.
- 마이그레이션: 기존 행은 `client_hash = sha256(client_id)` 로 채운 뒤 `client_id` 열을 빈 값으로 지운다 (열은 남겨 둬도 됨). `idx_items_client` 는 `(client_hash, id)` 로.
- 중복 방지(10분 안 같은 글)·`client_id` 당 하루 20회 제한도 `client_hash` 로 센다.
- 관리자 목록·상세의 `sender` 는 `client_hash`(없으면 `ip_hash`) 앞 8자로. `sender_total` 도 `client_hash` 기준.
- 로그·감사 기록에 `client_id` 원문을 남기지 않는다.

## 3. 본인 글 목록 `POST /mabimml/feedback/mine` — 응답에 필드 추가
요청은 그대로 `{"app":"MabiMML","client_id":"<32자리 16진수>"}`. 서버는 같은 솔트 해시를 계산해 같은 `client_hash` 의 글만(삭제 안 된 것, 최신 50개) 돌려준다.
```json
{"ok":true,"items":[{"id":"fb_12","created_at":"2026-11-18T01:02:03Z","nickname":"익명","kind":"question","message":"...","song":"...","status":"done",
  "replies":[{"message":"...","created_at":"..."}]}]}
```
- 추가: `nickname`. 그 밖(연락처·MML·버전·IP 해시·인증값)은 넣지 않는다.
- 형식이 틀리면 400 `bad_request`, IP 해시당 1분 30회 넘으면 429 (v1 그대로).
- 앱은 이 주소가 404/405/501 이면 "아직 볼 수 없어요" 안내를 보이니, 지울 일이 있으면 404 로.

## 4. 관리자 API — 필드 추가만
- `GET /mabimml/feedback/admin/items` 각 항목과 `GET .../items/{id}` 에 `nickname` 추가.
- `kind` 거르기에 `question` 허용.
- 답변 달기 `POST .../items/{id}/reply` 는 v1 그대로 (답변을 달면 status=done).
- 관리자 프로그램(`BUILD\mml\의견관리\의견관리.pyw`)도 서버 반영 뒤 '질문' 분류와 닉네임 칸을 보이게 따로 고칠 예정 (서버 작업과 무관).

## 5. 시험 (서버 venv 로)
`test_mabimml_feedback.py` 에 추가:
1. `nickname` 없이 쓰면 `/mine` 에서 `"익명"`, `"  남븝\n "` → `"남븝"`, 30자 → 20자
2. `kind:"question"` 이 그대로 저장·반환
3. DB 의 `items.client_id` 가 비어 있고 `client_hash` 만 채워짐 / 다른 `client_id` 로 `/mine` 하면 남의 글이 안 보임
4. v1 형식 DB 를 열면 마이그레이션 뒤 기존 글이 같은 `client_id` 의 `/mine` 에 그대로 보임
5. 관리자 목록에 `nickname` 이 있음

앱 쪽 시험용 가짜 서버(v2 동작 그대로): `BUILD\mml\의견관리\시험\fake_feedback_server.py` (표준 라이브러리, `python fake_feedback_server.py 8799 v2`).

## 6. 완료 기준 (실제 주소)
```
curl -s -X POST https://nambebmabi.com/mabimml/feedback -H "Content-Type: application/json; charset=utf-8" -H "X-MabiMML-Version: 3.1.1" -d "{\"app\":\"MabiMML\",\"version\":\"3.1.1\",\"nickname\":\"\",\"kind\":\"question\",\"message\":\"v2 시험 글입니다 (지워도 됨)\",\"contact\":\"\",\"song\":\"\",\"mml\":\"\",\"os\":\"windows x86_64\",\"client_id\":\"0123456789abcdef0123456789abcdef\"}"
curl -s -X POST https://nambebmabi.com/mabimml/feedback/mine -H "Content-Type: application/json" -d "{\"app\":\"MabiMML\",\"client_id\":\"0123456789abcdef0123456789abcdef\"}"
```
- 두 번째 응답의 방금 글에 `"nickname":"익명"`, `"kind":"question"` 이 있으면 됨
- 서버 DB 에서 `SELECT count(*) FROM items WHERE client_id<>''` 가 0
- 반영 방식은 v1 때처럼 `.updates\<이름>\` 에 backup·new·apply.ps1·rollback.ps1·README.md, 8765 의 그 server.py 만 재시작. DB 는 반영 전에 백업.
- 시험 글은 지우지 말고 알려 줘(관리자 프로그램에서 지우며 확인).
